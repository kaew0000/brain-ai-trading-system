# Ingestion Adapter — Phase W4

Read-only bridge between the trading engine and `world/data/runtime/`.
Full policy: `docs/architecture/SEPARATION_POLICY.md`. This document
covers the adapter's own internal design.

## Two orthogonal abstractions

**`DataSource`** (`world/readers/base.py`) — *how* to get raw content:
`JSONFileSource`, `CSVFileSource`, `SQLiteSource`, `LogFileSource`
(all working, stdlib-only), and `EventBusSource` (interface-only — no
event bus exists in this project yet). Swapping a reader's source
format never touches the reader's code.

**`Reader`** (`world/readers/base.py`) — *what* the raw content means.
Five concrete readers, each constructed with an injected `DataSource`
(never a hardcoded path):

| Reader | Returns | Matches schema |
|---|---|---|
| `JournalReader` | `list[JournalEntry]` | — (journal not yet schema'd; see Risks) |
| `TelemetryReader` | `list[TelemetryPoint]` | feeds `telemetry.schema.json` |
| `PortfolioReader` | `list[PortfolioPosition]` | feeds `portfolio.schema.json` |
| `MissionReader` | `list[Mission]` | `missions.schema.json` (Phase W1, reused) |
| `EventReader` | `list[Event]` | `events.schema.json` (Phase W1, reused) |

Every reader skips malformed rows rather than raising — one bad row
must never break a whole capture.

## Orchestration

`ReadOnlyIngestionAdapter` (`world/adapter/adapter.py`) holds up to
five `Reader` instances (all optional — "without assuming any one
exists today"), calls each `.read()`, and catches any exception as
"no data from that source this capture" rather than a fatal error.
Output: one `EngineSnapshot` (`world/adapter/engine_snapshot.py`),
which also records which sources were actually available
(`sources_available`).

`SnapshotBuilder` (`world/adapter/snapshot_builder.py`) turns one
`EngineSnapshot` into the six stable JSON shapes. `notifications.json`
is *derived* from `warning`/`critical` severity events — there is no
sixth reader, since the Phase W4 task's reader list has five entries
but the output contract has six files.

`RuntimeManager` (`world/runtime/runtime_manager.py`) is the only
class permitted to write `world/data/runtime/`. Its `run_once()` is
capture → build → write-if-changed, once per file, via
`SnapshotCache` (`world/runtime/cache.py`) — a content-hash comparison
that skips a write when nothing changed (see `RUNTIME_DATA_FLOW.md`).

## What's NOT wired

No reader is constructed with a real `DataSource` pointing at an
actual engine file anywhere in this repo. `world/data/runtime/*.json`
are honest empty/idle placeholders, generated by actually running the
pipeline with zero readers configured — not hand-written. Pointing a
real `DataSource` at a real engine-emitted file is future work (a
later phase, once the trading engine team confirms what it already
emits, or is asked to emit something new — out of scope for Phase W4,
which was explicitly forbidden from touching `journal/`, `telemetry/`,
`database/`, etc.).
